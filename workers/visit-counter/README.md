# عدّادُ دخولِ شوجب — Cloudflare Worker

بديلُ سيرِ n8n «شوجب — عدّاد الدخول». **يُرجِعُ شكلَ الاستجابةِ نفسَه حرفياً**، فلا
يتغيّرُ في المنصّةِ إلا سطرانِ في `js/unlock.js`.

## لماذا نُقِل (سببٌ مقيسٌ لا تفضيل)

رصيدُ تنفيذاتِ n8n **حسابٌ واحدٌ مشتركٌ مع مسارَي تفعيلِ رموزِ الشراء**. والعدّادُ
ينفقُ تنفيذاً لكلِّ جهازٍ في اليوم (مئاتٌ يومياً) بينما التفعيلُ ينفقُ عشراتٍ في الشهر.
فاستنفدَ العدّادُ الرصيدَ في **ستّةِ أيّام** (تنفيذ `3292`، ٢٠٢٦-٠٩-١٣:
`Execution limit reached`) — **وتوقّفَ معه تفعيلُ الرموزِ صامتاً**، فمن دفعَ لم
يُفتَحْ له الكتاب. القاعدةُ كاملةً في `CLAUDE.md` §رصيدُ تنفيذاتِ n8n مشترك.

| | n8n (قبل) | Cloudflare (بعد) |
|---|---|---|
| السقفُ المجّانيّ | ‏٢٥٠٠–١٠٠٠٠ **شهرياً** | ‏١٠٠٬٠٠٠ **يومياً** |
| الاستهلاكُ المقيس | ‏≈٩١٠٠ شهرياً | الشيءُ نفسُه = **٠٫٣٪ من السقف** |
| يشاركُه التفعيل؟ | ✅ **نعم — وهو الخطر** | ⛔ لا، معزولٌ تماماً |
| ذرّيّةُ الزيادة | قراءةٌ ثمّ كتابةٌ بعقدتَين | `ON CONFLICT DO UPDATE` في عبارةٍ واحدة |
| ساعةُ الزيارة | ⛔ لا تُحفَظ | ✅ تُحفَظ |

## خطواتُ النشر

تُنفَّذُ **مرّةً واحدة**، من داخلِ هذا المجلَّد (`workers/visit-counter/`).

```bash
cd workers/visit-counter
npm install
```

**١) حسابُ Cloudflare** — مجّانيٌّ من <https://dash.cloudflare.com/sign-up>.
> ⛔ **ولا يُنقَلُ نطاقُ `shoogp.com` إلى Cloudflare ولا يُمَسُّ إطلاقاً.** الـWorker
> يسكنُ نطاقَ `workers.dev` المجّانيَّ، والموقعُ يبقى على GitHub Pages كما هو.

**٢) تسجيلُ الدخول:**
```bash
npx wrangler login
```

**٣) إنشاءُ قاعدةِ البيانات:**
```bash
npx wrangler d1 create shoogp-visits
```
يطبعُ `database_id` — **انسخْه إلى `wrangler.toml`** مكانَ `ضع-هنا-معرّف-قاعدة-البيانات`.

**٤) بناءُ الجدولَين:**
```bash
npx wrangler d1 execute shoogp-visits --remote --file=schema.sql
```

**٥) بذرُ التاريخِ المنقولِ من n8n** (‏١٥ يوماً · ٤٢٠٧ زيارة):
```bash
npx wrangler d1 execute shoogp-visits --remote --file=seed.sql
```
> `INSERT OR IGNORE` فيه، فإعادةُ تشغيلِه آمنةٌ ولا تُضاعِفُ رقماً.

**٦) مفتاحُ قراءةِ الأرقام** — يُكتَبُ سرّاً لا في الملفّات:
```bash
npx wrangler secret put STATS_KEY
```
وأدخلْ عندَ السؤال: `shoogp2026` (‏`DEV_PASS` نفسُه في `js/unlock.js`).
> ⚠️ **وهو سترٌ لا أمان** — يظهرُ لمن فتحَ مصدرَ الصفحة، وكذلك كان في n8n. ولا خطرَ
> فيه: أقصى ما يُتيحُ قراءةَ أعدادٍ مجمّعةٍ لا بيانات.

**٧) النشر:**
```bash
npx wrangler deploy
```
يطبعُ العنوان: `https://shoogp-visits.<نطاقُك>.workers.dev`.

**٨) ربطُ المنصّة** — في `js/unlock.js` §مصدرُ العدّاد، **سطرانِ لا غير**:
```js
var COUNTER = 'cf';                                    // كانَ 'n8n'
var CF_BASE = 'https://shoogp-visits.<نطاقُك>.workers.dev';
```
ثمّ ادفعْ إلى `main` فتُنشَرُ الصفحةُ تلقائياً.

> **وبهذَين السطرَينِ يُشتغِلُ قِمْعُ الكتبِ أيضاً** (§أدناه) — فهو معطَّلٌ على n8n
> بحارسٍ في الكود، **ومُتحقَّقٌ منه حيّاً: صفرُ نبضاتٍ ما دامَ `COUNTER === 'n8n'`**.

> ⏰ **والأنظفُ أن يكونَ التحويلُ بعدَ منتصفِ ليلِ مسقط** فلا يُقسَمُ يومٌ واحدٌ بينَ
> عدّادَين. وإن حُوِّلَ نهاراً فزيارةُ ذلك اليومِ تبدأُ من صفرٍ في Cloudflare —
> يُصلَحُ بسطرٍ واحد (ضعْ مكانَ `NN` ما تعرضُه الشارةُ قبلَ التحويل):
> ```bash
> npx wrangler d1 execute shoogp-visits --remote \
>   --command "INSERT INTO days (day,visits) VALUES ('2026-09-21',NN) \
>              ON CONFLICT(day) DO UPDATE SET visits = visits + NN"
> ```

**٩) التحقّق** — افتحِ الموقعَ بوضعِ المطوّرِ (`?dev=shoogp2026`) وانظرِ الشارة:
الإجماليُّ يكملُ من حيثُ وقفَ ولا يبدأُ من صفر. ثمّ:
```bash
npx wrangler d1 execute shoogp-visits --remote \
  --command "SELECT day, visits FROM days ORDER BY day DESC LIMIT 5"
```

**١٠) إطفاءُ عدّادِ n8n** — بعدَ يومٍ من التحقّق، أوقفْ سيرَ «شوجب — عدّاد الدخول»
(‏`gbrWKUOlJbN7H0X0`) من لوحةِ n8n. **وهنا يتحرّرُ الرصيدُ لمسارَي التفعيل** وينتهي
خطرُ تعطّلِ البيع.
> ⛔ **ولا يُحذَفُ السيرُ ولا جدولُه** — يبقى مرجعاً للأرقامِ الأصليةِ إن لزمت مطابقة.

## 📚 قِمْعُ الكتب — تقديرُ المشتريات (قرارُ المالك ٢٠٢٦-٠٩-٢١)

**عدّادُ الزياراتِ يقيسُ أجهزةً، والجهازُ ليس وحدةَ الشراء.** سبّورةُ الفصلِ الواحدةُ
تستعملُها ثلاثُ معلّماتٍ في اليومِ فتُحسَبُ **واحدة**، وقد تفتحُ كلٌّ منهنّ مادّةً
مختلفةً — أي **ثلاثَ فرصِ شراءٍ تُقرَأُ فرصةً واحدة**.

**فالوحدةُ هنا (جهاز × كتاب × مرحلة × يوم)** — الجهازُ يُحسَبُ **مرّةً لكلِّ كتابٍ**
يفتحُه، فتظهرُ المادّتانِ على اللوحِ الواحدِ مادّتَين.

| المرحلة | متى تُرسَل | موضعُها في الكود |
|---|---|---|
| `open` | **فُتِحَ الكتاب** — الفرصة | `openBook` في `js/app.js` |
| `lock` | **نُقِرَ درسٌ مقفولٌ فيه** — الاهتمام | `nudge` في `js/unlock.js` |
| `code` | **فُتِحَت نافذةُ الرمز** — نيّةُ الشراء | `ask` في `js/unlock.js` |

وتعرضُها الشارةُ مجموعةً `📚 ٤٧ ← ١٢ ← ٣`، وفي التلميحِ تفصيلُها **بالكتاب** مرتَّباً
بالأقربِ إلى الشراء.

> ⚠️ **وهو يقيسُ الفرصةَ لا البيع.** عددُ المشترياتِ الحقيقيُّ في جداولِ الرموزِ
> بدرايف — **وقيمةُ القِمْعِ أن يُقرأَ بالنسبةِ إليه**: كم `code` لزمَت لبيعةٍ واحدة.
> وبعدَ أسبوعٍ تصيرُ تلك النسبةُ معاملاً يُقدَّرُ به بيعُ الغدِ من قِمْعِ اليوم.

> ⛔ **ولا يعملُ على n8n إطلاقاً** — نبضاتُه أضعافُ نبضةِ الزيارةِ فتستنزفُ الرصيدَ
> المشتركَ مع تفعيلِ الرموز. الحارسُ في الكود (‏`BOOK_URL = null` على n8n)،
> **ومُتحقَّقٌ منه حيّاً: صفرُ نبضاتٍ بعدَ فتحِ كتابَين.**

> **ولو كنتَ نشرتَ الـWorker قبلَ هذه الإضافة،** أعِدْ تشغيلَ `schema.sql` وحدَه
> ليُنشأَ جدولُ `books` — فيه `IF NOT EXISTS` فلا يمسُّ بياناتِك:
> ```bash
> npx wrangler d1 execute shoogp-visits --remote --file=schema.sql
> ```

## ما الذي صارَ ممكناً ولم يكن

جدولُ `hits` يحفظُ **ساعةَ الزيارة**، فتُرجِعُ `/stats` حقلَ `refSoFar`:
**نظيرُ اليومِ من الأسبوعِ الماضي عندَ هذه الساعةِ نفسِها**. فتعرضُ الشارةُ
`اليوم ٩٢ ⏳ ↔ ٣٤٠` — وهي المقارنةُ الصادقةُ التي تعذّرت في n8n لأنّها تضاعفُ
الكتابةَ في رصيدٍ محدود.

> ⚠️ **ولا يمتلئُ إلا بأسبوعٍ من التشغيل.** قبلَه يُرجِعُ `refHasHours:false`
> **والشارةُ تُخفي السطرَ من تلقائِها** — ولا شيءَ يُكسَر.

## الخصوصية

**لا يُخزَّنُ إلا `(اليوم، العدد)` و`(اليوم، الساعة، العدد)`.** لا IP ولا مُعرِّفٌ
ولا كوكيز ولا بصمةُ متصفّح — وفاءً بنصِّ `privacy.html`. ووحدةُ العدِّ «جهازٌ فتحَ
الموقعَ اليوم» يحرسُها `localStorage` في متصفّحِ المعلّمةِ نفسِه لا الخادم.
